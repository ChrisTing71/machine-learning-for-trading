# 第 2 章導讀:金融資料的全貌

整理日期:2026-10-06

## 這一章到底在講什麼

這一章的主張是:資料不是中立的原料,每一份資料集都偷偷替你做了決定。

同樣叫「收盤價」,有沒有還原除權息、時間戳記是哪個時區、代碼對應到哪家公司、數字事後有沒有修訂,答案不同,研究結論就不同。很多看起來很漂亮的回測,其實是資料缺陷製造出來的。

整章分四塊,共 22 本筆記本:

- 2.1 資料有哪幾類(沒有筆記本)
- 2.2 各資產類別的資料長什麼樣(筆記本 01 到 12)
- 2.3 怎麼檢查資料能不能信(筆記本 13 到 16)
- 2.4 資料該怎麼存(筆記本 17 到 22)

這份導讀是根據資料夾裡的 README 和筆記本整理的,不是根據書的內文。2.1 沒有對應的筆記本,所以那一節只有 README 摘要的深度。

## 先搞懂的幾個詞

這些詞在 22 本筆記本裡反覆出現,先有個印象會讀得順很多。

| 名詞 | 白話意思 |
| --- | --- |
| OHLCV | 開盤、最高、最低、收盤、成交量,一根 K 棒的五個數字 |
| panel | 很多標的、很多日期疊在一起的資料表 |
| 股票池 (universe) | 你的策略可以挑選的所有標的 |
| 公司行動 (corporate action) | 股票分割、配息這類會讓股價跳動、但不是真正漲跌的事件 |
| 調整後價格 (adjusted) | 把分割和配息的影響還原後的價格,算報酬要用它 |
| 倖存者偏誤 (survivorship bias) | 資料裡只剩活下來的公司,回測因此看起來比實際好 |
| 時點正確 (point-in-time) | 回測的每一天只用當天真的已經知道的資料 |
| 前視偏誤 (lookahead bias) | 不小心用到了未來的資訊,時點正確的反面 |
| 轉倉 (roll) | 期貨或選擇權快到期時,換到下一個合約 |
| 連續序列 (continuous) | 把一個個會到期的合約接成的長期價格線,是人造的 |
| 交易時段 (session) | 交易所定義的「一天」,不一定是午夜到午夜 |
| 不變條件 (invariant) | 一定要成立的關係,例如最高價不能低於收盤價 |
| Parquet | 一種壓縮的欄式檔案格式,本書的預設儲存方式 |

## 各節重點

### 2.1 金融資料的分類

資料分三大類:市場資料(價格、成交量)、基本面資料(財報)、另類資料(文字、衛星影像等)。但這一節更重要的訊息是,每份資料集都內含四種定義:時間戳記、價格調整、識別代碼、修訂方式。這四件事決定了資料在研究中真正的意思。

### 2.2 各資產類別的市場資料

「價格」「流動性」在不同市場的意思不一樣。股票有除權息,期貨合約會到期要換月,選擇權有到期日和履約價,加密貨幣永續合約有資金費率,外匯沒有集中交易所。市場結構不同,資料的處理方式就不同。

### 2.3 資料來源的盡職調查

這是全章的風險控管核心。重點檢查四種金融資料特有的毛病:用了當時還不知道的資訊(時點錯誤)、只留下活下來的公司(倖存者偏誤)、除權息處理錯誤、代碼對不上。另外還要評估供應商的品質、法律授權和技術面。

### 2.4 儲存資料

沒有一套儲存方案適合所有人。選擇取決於你怎麼讀資料、資料多大、多少人同時用。這一節實際測了檔案格式、內嵌式資料庫和伺服器資料庫的速度,並給出一個研究用途的預設架構。

## 各本筆記本在做什麼

每本筆記本都在回答一個問題。下面依資產類別分組,每本列出它問什麼、答案是什麼。

### 股票與 ETF(01 到 03)

| 筆記本 | 它在問什麼 | 答案 |
| --- | --- | --- |
| 01 美股探索 | 這份美股資料裡到底有哪些公司? | 2014 年以前沒有任何公司「離開」的紀錄,代表那段期間只留下了活下來的公司 |
| 02 公司行動 | 股票分割和配息會怎麼扭曲價格? | 不調整的話,一次 2:1 分割看起來像跌了 50%。算報酬要用調整後價格,模擬下單要用原始價格 |
| 03 ETF 探索 | 這 100 檔 ETF 的資料可靠嗎? | 數量只增不減,代表清單是事後挑的,同樣有倖存者偏誤。各組成交量差超過十倍 |

01 和 03 要對照著看。股票資料的公司數先升後降,ETF 的數量升上去就持平。兩種形狀都不是市場的樣子,而是資料怎麼被收集的痕跡。

03 還有一個小教訓:檢查「最高價要大於等於收盤價」時有幾百列失敗,但差距只有浮點數的最後一個位元。那是計算誤差,不是資料錯誤。看到檢查失敗,先量差了多少再下結論。

### 期貨(04 到 06)

期貨最大的麻煩是合約會到期。要得到一條長期的價格線,必須把一個個合約接起來,這個動作叫轉倉。

| 筆記本 | 它在問什麼 | 答案 |
| --- | --- | --- |
| 04 期貨探索 | 期貨資料的結構是什麼? | 分三層:商品(ES)、合約(ESH4)、連續序列。連續序列是人造的,沒有人真的交易過它 |
| 05 交易時段彙總 | 小時 K 棒怎麼合成日 K 棒? | 要照交易所的交易時段切,不能照午夜切。週日晚上的交易屬於週一 |
| 06 連續合約 | 轉倉時的價格缺口怎麼處理? | 兩種調整法各保留不同的東西,見下表 |

| 調整方法 | 做法 | 保留什麼 | 適合 |
| --- | --- | --- | --- |
| Panama(加法) | 把缺口加到所有舊價格上 | 金額損益 | 回測損益 |
| 比率(乘法) | 把舊價格乘上新舊合約的價格比 | 百分比報酬 | 統計分析、特徵 |
| 不調整 | 照原樣 | 實際報價 | 實盤下單、比較不同月份的合約 |

06 最值得記的是驗證那一段。作者拿自己接的序列和供應商的比,一開始差很多。原因是一邊是日資料、一邊是小時資料,時間沒對齊。對齊之後,除了轉倉那幾天,兩邊每天完全相同。

### 選擇權(07 到 09)

選擇權資料比股票多兩個維度:履約價和到期日。同一檔股票同一天有幾百個選擇權報價。

| 筆記本 | 它在問什麼 | 答案 |
| --- | --- | --- |
| 07 選擇權探索 | 選擇權資料裡有什麼?哪些能用? | 約三分之一的隱含波動度是供應商估出來的,不是算出來的,要先濾掉 |
| 08 Greeks 計算 | 自己算的 Greeks 和供應商的一樣嗎? | 大致相同。差距的一大部分來自利率:2020 年利率跌了超過一個百分點,不能用固定值 |
| 09 連續選擇權 | 「30 天期選擇權」的價格序列能直接算報酬嗎? | 不能。它幾乎每天都在換合約,算出來的報酬大部分是假的 |

09 和 06 是同一個問題的兩個版本。期貨一年換四次合約,粗略處理還過得去。選擇權平均不到兩天就換一次,所以必須追蹤「進場的那個合約後來變多少錢」,才是真實報酬。

07 還示範了三個常見名詞在圖上的樣子:微笑曲線(遠離現價的履約價波動度較高)、期限結構(不同到期日的波動度)、以及 2020 年 3 月波動度飆升得快、退得慢。

### 加密貨幣與外匯(10 到 12)

這三本處理的都是幾乎全天候交易的市場,沒有「收盤」這個自然的切點。

| 筆記本 | 它在問什麼 | 答案 |
| --- | --- | --- |
| 10 永續合約探索 | 幣安的價格和溢價資料可靠嗎?怎麼合併? | 價格每小時一筆,溢價每 8 小時一筆。合併時要把溢價的時間往後推 8 小時,否則會偷看未來 |
| 11 溢價分析 | 溢價怎麼變成資金費率? | 資金費率有超過三分之一的時間剛好等於固定利率。而且溢價平均是負的,資金費率平均卻是正的 |
| 12 外匯探索 | 外匯資料的「一天」從哪裡切? | 從紐約下午 5 點切,不是 UTC 午夜。切錯會多出數千個只有一根 K 棒的假日子 |

先解釋幾個詞。永續合約是沒有到期日的期貨。為了讓它的價格不要偏離現貨太遠,交易所每 8 小時讓多空雙方互付一筆錢,這筆錢的比率叫資金費率。溢價指數衡量永續合約比現貨貴或便宜多少,資金費率就是用它算出來的。

10 有一個很好的教訓。溢價資料裡每七筆就有一筆剛好是零,看起來像缺資料被填成零。其實不是:幣安的公式在價差很小時本來就會算出零。看到奇怪的數字,先去讀它的定義,不要急著當成錯誤刪掉。

12 的提醒是外匯沒有集中交易所,所以資料裡的「成交量」只是這家券商更新報價的次數,不是真正的成交金額。

05、10、12 三本講的是同一件事:時間戳記代表什麼、一天從哪裡切,每個市場都不一樣,而且切錯了資料看起來仍然很正常。

### 資料品質檢查(13 到 16)

前面 12 本是認識資料,這 4 本是質疑資料。它們對應 2.3 節,是全章最重要的部分。

| 筆記本 | 它在問什麼 | 答案 |
| --- | --- | --- |
| 13 品質架構 | 怎麼自動找出可疑的資料? | 四類檢查:結構是否合理、有沒有異常值、分配有沒有漂移、有沒有缺口或重複。但工具只能指出可疑之處,不能判斷是不是錯誤 |
| 14 時點驗證 | 我的特徵有沒有偷看未來? | 總經資料的日期是「數字描述的月份」,不是「公布的日期」。直接用會早好幾週就知道數字 |
| 15 倖存者偏誤 | 只用活下來的公司回測,會高估多少? | 會高估。但要先修掉幾筆錯誤的價格,否則連結論的方向都會相反 |
| 16 供應商比較 | 兩家供應商的價格為什麼不一樣? | 通常不是資料錯,而是除權息的調整基準不同 |

這四本有一個共同的態度,值得記下來。

- **檢查通過不代表沒問題**。13 先故意塞進三筆錯資料,確認檢查工具真的抓得到,才相信它的「全部通過」。
- **異常不等於錯誤**。13 找到的最大「異常」其實是股票分割和財報暴跌,都是真的事件。
- **檢查有先後順序**。15 裡只有極少數幾筆錯誤價格(破產重整後沿用舊代碼的股票),卻足以讓結論從「高估」變成「低估」。
- **看差異的形狀,不要只看平均**。16 指出:每天都差同樣比例是調整基準不同,某天突然跳一階是日期標錯,每天差一點點是四捨五入。

14 還示範了一種常見的偷看未來:置中移動平均。它把前後幾天一起平均,所以有一半的輸入是當天還沒發生的價格。線看起來更貼近價格,但實盤算不出來。

### 管線與儲存(17 到 22)

最後六本偏工程面:資料怎麼自動抓、怎麼存、用什麼工具讀。第一次讀可以先跳過,等真的要建自己的資料庫時再回來。

| 筆記本 | 它在問什麼 | 答案 |
| --- | --- | --- |
| 17 完整管線 | 怎麼把兩家供應商的歷史接成一條? | 接縫處要乘一個比例對齊調整基準,並為每一列記下來源 |
| 18 資料管理 | 有沒有現成工具可以管這些? | 有,ml4t-data 的 DataManager。資料依年月分資料夾存成 Parquet |
| 19 增量更新 | 每天更新要重抓全部嗎? | 不用,只抓新的。但不要抓當天還沒收盤的那一根 |
| 20 檔案格式 | CSV、Parquet、Feather、HDF5 哪個好? | 沒有全贏的。長期儲存用 Parquet,本機工具之間交換用 Feather |
| 21 資料庫引擎 | DuckDB、SQLite、ClickHouse 等哪個快? | 欄式引擎(DuckDB、ClickHouse)做分析快。筆記本刻意不指名冠軍,要你在自己機器上跑 |
| 22 pandas 對 Polars | 該用哪個 DataFrame 工具? | 資料少於 10 萬列都可以,超過 100 萬列用 Polars,畫圖時轉回 pandas |

這幾本背後有一個共同的觀念:列式與欄式儲存。CSV 和傳統資料庫一列一列存,要讀一個欄位也得掃過整列。Parquet 和 DuckDB 一欄一欄存,只要收盤價就只讀收盤價那一欄。金融分析幾乎都是「少數幾欄、很多列」,所以欄式比較合適。

20 到 22 還示範了怎麼做公平的效能比較:兩邊要算同一件事、用同一套計時規則、結果要先驗證相同才比速度。22 裡就有兩組測試原本兩邊算的東西不一樣,比較根本不成立。

## 容易卡住的觀念

這一章的難點不在數學,而在每個市場有自己的行話。下面依資產類別列出最常卡住的詞。

| 市場 | 名詞 | 白話意思 |
| --- | --- | --- |
| 期貨 | 近月合約 | 最快到期、通常交易最熱絡的那個合約 |
| 期貨 | Panama 與比率調整 | 消除轉倉缺口的兩種方法,一個用加的、一個用乘的 |
| 期貨 | 跨月價差 | 兩個不同到期月份合約之間的價格差 |
| 選擇權 | 履約價與到期日 | 合約約定的買賣價格和最後期限 |
| 選擇權 | 價內、價平、價外 | 現在履約有賺、差不多、沒賺 |
| 選擇權 | 隱含波動度 (IV) | 從選擇權價格反推出來、市場預期的未來波動 |
| 選擇權 | Greeks | 選擇權價格對各種因素的敏感度。Delta 對股價,Vega 對波動度,Theta 對時間 |
| 選擇權 | 跨式 (straddle) | 同時買同履約價的買權和賣權,賭波動大小而不賭方向 |
| 加密貨幣 | 永續合約 | 沒有到期日的期貨 |
| 加密貨幣 | 資金費率 | 多空雙方每 8 小時互付的費用,用來把合約價拉回現貨價 |
| 外匯 | 基礎貨幣與報價貨幣 | EURUSD 是一歐元值多少美元,歐元是基礎、美元是報價 |
| 資料品質 | PSI | 衡量近期資料的分配和過去差多少的指標 |
| 資料品質 | 版本 (vintage) | 某個日期當時看到的數字,相對於事後修訂過的數字 |
| 儲存 | as-of 合併 | 把每一列對到「當時最新的那一筆」,而不是時間完全相同的那一筆 |

有一個觀念貫穿整章:資料出錯時通常不會報錯,而是安靜地給你一個看起來合理的數字。時間切錯、調整基準不同、合約換掉了,程式都照樣跑得完。所以作者反覆示範同一個動作:不要只看有沒有通過,要去量差了多少、差在哪裡。

## 讀完該帶走什麼

你不需要記住 22 本筆記本的細節,只需要記住拿到任何新資料時要問的五個問題。

- 這份資料的價格有沒有調整過?用的是哪一種調整?
- 時間戳記代表什麼?是開始還是結束、哪個時區、是事件發生的時間還是公布的時間?
- 資料裡有沒有已經消失的標的?從什麼時候開始有記錄?
- 這個數字事後有沒有被修訂過?當時看到的是多少?
- 檢查通過了,但這個檢查真的抓得到錯誤嗎?

### 建議的閱讀順序

22 本不必依序讀完。依你關心的市場挑著讀就好。

1. 先讀 01、02、03。股票與 ETF 最直覺,也建立「調整後價格」和「倖存者偏誤」兩個基本觀念。
2. 接著讀 13、14、15。這是全章最重要的三本,教你怎麼質疑資料。
3. 再依興趣選資產類別:期貨讀 04 到 06,選擇權讀 07 到 09,加密貨幣讀 10、11,外匯讀 12。
4. 16 到 22 等要建自己的資料庫時再讀。

每本筆記本都先看最後的「重點整理」,再回頭看圖和圖後面的文字,程式碼最後才看。選擇權那三本最難,沒有選擇權基礎的話可以先跳過。
